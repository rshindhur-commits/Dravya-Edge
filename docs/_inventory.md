# Repository Inventory

Read-only static inventory of the scanner/dashboard codebase. Generated by direct
inspection of the code (AST symbol extraction, grep of call sites, and manual
tracing of the P&L-relevant paths) as of 2026-07-25, `Claude_Changes` branch
(`f99e690` + local hygiene commits). Nothing in this document changes behavior;
it exists to answer "where does X live" and "what calls what" without re-deriving
it by hand each session.

Regenerate by re-running the same static analysis if the module list drifts —
this file is a snapshot, not a build artifact.

### Path A — legacy live-trade branch (`app/state/trade_state.json`)

Runs **inline inside `_run_scanner_impl`**, gated on

  -> alerts/telegram_alerts.py :: maybe_send_trade_open_alert(active_trade, ...)
```

On a later scan, if `exit_setup["exit_signal"]` is true for this state:

```
alerts/telegram_alerts.py :: maybe_send_trade_exit_alert(

### Path B — paper trading (`app/state/paper_trade_state.json`) — **the authoritative P&L store**

Triggered from a **separate process/entry point**: `app/dashboard.py`'s own
refresh cycle (`_run_auto_paper_entries`, `dashboard.py:9343-9356`), not from
`app/main.py`. It reads back the `Candidate Entry Price` / `Candidate Stop
Price` / `Candidate Target Price` / `Option Ticker` columns Path A's risk/option
computation already wrote onto the scanner output row — it does not recompute
risk or re-rank options itself.

```
app/dashboard.py :: _run_auto_paper_entries()
  -> app/runtime/paper_automation.py :: run_auto_paper_entries(candidates, controls)
       for each ENTER_PAPER / eligible candidate row:
         paper_automation_support.py :: _auto_paper_entry_reason(row, controls, paper_trades)
           -> gates/entry_gate.py :: evaluate_entry_gate(mode="paper")
           -> state/holding_policy.py :: derive_holding_profile()
         if allowed:
           state/paper_trade_manager.py :: open_paper_trade(
               symbol, direction,
               entry_price =row["Candidate Entry Price"],
               stop_loss   =row["Candidate Stop Price"],
               take_profit =row["Candidate Target Price"],
               option_ticker/bid/ask =row["Option Ticker"/"Option Bid"/"Option Ask"])
             -> writes app/state/paper_trade_state.json
             -> state/suggested_trade_manager.py :: promote_suggestion_to_paper_trade()
           alerts/telegram_alerts.py :: maybe_send_paper_entry_alert(opened_trade, ...)
             -> gated by _entry_alert_policy() thresholds (min_rr, min_option_quality,
                max_spread_pct) via gates/entry_gate.py::evaluate_entry_gate(mode="telegram")
             -> this is the actual "NEW TRADE" subscriber message
```

```
app/dashboard.py :: _run_auto_paper_entries()  (same refresh cycle)
  -> app/runtime/paper_automation.py :: run_auto_paper_exits(df, controls)
       for each OPEN paper trade:
         paper_automation_support.py :: _auto_exit_reason(trade, current_price, scanner_row, controls)
           - stop/target hit: independent direct compare against
             trade["stop_loss"] / trade["take_profit"] (NOT a re-call to evaluate_exit)
           - live exit signal: reads scanner_row["Live Exit Signal"/"Live Exit Reason"]
             (which DID come from exit_engine.evaluate_exit() during Path A's scan)
           - profit-threshold: _calculate_trade_r_progress(trade, current) >= controls["profit_r"]
           - EOD: holding_policy(trade).force_eod_exit at 15:55 ET
         if reason:
           paper_automation_support.py :: _close_paper_trade(symbol, current_price, ...)
             -> state/paper_trade_manager.py :: close_paper_trade(symbol, close_price, exit_reason)
                  -> _paper_trade_result(trade, close_price)   ***the actual P&L formula***
                       is_short = direction == "PUT"
                       pnl = (entry - close) if is_short else (close - entry)
                       risk = (stop - entry) if is_short else (entry - stop)
                       pnl_pct    = round(pnl / entry_price * 100, 2)
                       r_multiple = round(pnl / risk, 2)              # if risk > 0
                       outcome    = TARGET_HIT / WIN / LOSS / FLAT
                  -> _append_paper_trade_event(trade, "AUTO_EXIT"/"MANUAL_CLOSE")
                       -> data/daily/YYYY-MM-DD/paper_trade_events.csv (immutable)
                  -> _append_trend_capture_for_closed_trade(trade)
                       -> indicators/technical_indicators.py :: get_polygon_data() + compute_indicators()
                          (re-fetches 5m candles for the trade's window)
                       -> analytics/trend_capture.py :: analyze_trend_capture(), build_trend_capture_row()
                            Trend Capture % = max(0, min(100, final_R / MFE_R * 100))
                       -> analytics/trade_snapshot.py :: append_trade_exit_snapshot()
                       -> db/artifact_persistence.py :: persist_completed_trade()  (RuntimeJob, best-effort)
                  -> _save_paper_trade_telemetry(trade)
                       -> analytics/trade_telemetry.py :: save_trade_telemetry()
                  -> alerts/telegram_alerts.py :: maybe_send_trade_exit_alert(
                         pnl_pct=trade["pnl_pct"], r_multiple=trade["r_multiple"],
                         trend_capture_pct=trend_capture_row["Trend Capture %"])
                       -> this is the "TRADE CLOSED" subscriber message
```

**Downstream consumers of Path B's numbers** (all read-only, all derived):
`app/ui/cache/validation_state_builder.py` (Today's Performance, Trade Doctor),
`app/ui/dashboard_state.py` (`today_performance`), `analytics/expectancy_engine.py`,
`analytics/trading_scorecard.py`, `tools/daily_validation_report.py`.

### Why this split matters when reading the code

- `Candidate RR`, entry/stop/target on a **scanner row** and on a **paper trade**
  are computed at different times by different formulas that happen to usually
  agree: the scanner row's numbers come from `risk_manager.calculate_risk()` at
  scan time; the paper trade's realized R comes from `_paper_trade_result()` at
  close time, using the *entry-time-frozen* stop/target stored on the trade, not
  a re-evaluation.
- Manual paper-close and dashboard-triggered auto-exit both funnel through the
  same `close_paper_trade()` → `_paper_trade_result()` — there is exactly one
  P&L formula for paper trades, which is good; but there are two *open* paths
  (`open_paper_trade` from `dashboard.py:4335`, `dashboard.py:4928`, and
  `paper_automation.py:187`) writing to the same store, gated respectively by
  `ENABLE_MANUAL_PAPER_ENTRIES`/`SHOW_MANUAL_PAPER_BUTTONS` (both `false` by
  default) and `AUTO_PAPER_ENABLED`.
- `exit_engine.evaluate_exit()` (Path A) is *not* what actually closes a paper
  trade — it only supplies the `Live Exit Signal`/`Live Exit Reason` columns
  that `_auto_exit_reason()` (Path B) treats as one of several inputs alongside
  its own independent stop/target/profit/EOD checks.

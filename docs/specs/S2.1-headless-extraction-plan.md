## 1. The headline finding: there is almost nothing to extract

The plan's premise is that auto-paper decision logic is entangled with
Streamlit and must be disentangled. **It is not entangled.** Measured:

| Module | Lines | Streamlit references |
|---|---|---|
| `runtime/paper_automation.py` | 345 | **0** |
| `runtime/paper_automation_support.py` | 488 | **0** |
| `state/paper_trade_manager.py` | 1,112 | **0** |
| `gates/entry_gate.py` | 667 | **0** |
| `state/holding_policy.py` | 88 | **0** |

**The entire decision path is already Streamlit-free.** `dashboard.py` is a
*caller*, not a host. S2.2 is therefore not an extraction — it is writing a
**second caller** that assembles the same inputs and invokes the same functions
in the same order.

This materially shrinks Phase 2 and materially raises the importance of S2.3:
since no logic moves, any parity failure is an **input-assembly** or
**ordering** difference, not a logic port error. Those are precisely the
failures that are easy to miss and easy to test for.

## 3. Input contract

### 3.1 Controls — already persisted, no UI dependency

`controls` is a 9-key dict built from `st.sidebar` widgets, but every key
resolves through a three-tier chain:

```
st.session_state  →  app/state/auto_paper_settings.json  →  env var / literal default
```

`_save_auto_paper_settings()` rewrites the JSON on **every dashboard render**
(`dashboard.py:4054`), so the file is always current with the UI. The headless
caller reads tier 2, falling back to tier 3.

| Control key | JSON key | Fallback |
|---|---|---|
| `auto_paper_enabled` | `auto_paper_enabled` | `AUTO_PAPER_ENABLED` env, default `True` |
| `max_daily` | `auto_paper_max_daily` | 3 |
| `min_setup` | `auto_paper_min_setup` | — |
| `min_rr` | `auto_paper_min_rr` | — |
| `direction` | `auto_paper_direction` | `"Both"` |
| `auto_exit_enabled` | `auto_paper_exit_enabled` | — |
| `eod_close_enabled` | `auto_paper_eod_close_enabled` | — |
| `restore_multiday_positions` | `restore_multiday_positions` | — |
| `profit_r` | `auto_paper_profit_r` | — |

**S2.2 must extract the tier-2/3 resolution into a shared function that both
callers use.** If the headless path re-implements the defaults, they will drift,
and S2.3 will not catch it — because both paths would still agree whenever the
JSON exists. This is the single most likely silent divergence in the phase.

### 3.2 Scanner row columns consumed

31 columns are read by the automation path. S2.2's loader must produce all of
them; S2.3 must assert on the assembled frame, not just on the decisions.

```
15m Score · Action Status · Affordability Status · Affordable · Blocked By
Candidate Direction · Candidate RR · Entry · Event Blocked · Execution Ready
Live Exit Reason · Live Exit Signal · Max Allowed Contract Cost · Option Ask
Option Bid · Option Contract Cost · Option Quality Score · Option Quote Age Minutes
Option Spread % · Paper Trade Opened · RR · Real Review Scan Count
Real Trade Readiness · Realtime Block Reason · Realtime Ready · Regime Blocked
Risk Reward · Setup % · Setup Valid · Symbol · Top Candidate
```

Plus `Price`, read frame-level for current prices (`paper_automation.py:284`).

Three of these are **produced by the dashboard enrichments in step C**, not by
the scanner: `Paper Trade Opened`, `Real Trade Readiness`, `Real Review Scan
Count`. They do not exist in `scanner_output.xlsx`. A headless caller that loads
the scanner file and calls the automation directly **will silently make
different decisions**, because these columns will be missing and every
`.get()` will return `None`.

## 4. The three behaviours that will break parity if missed

These are the reason S2.3 exists. Each is a real, verified property of the
current path that a naive headless loop would get wrong.

### 4.1 `st.rerun()` after exits means entries are skipped that pass

```python
auto_closed = run_auto_paper_exits(df, auto_paper_controls)
if auto_closed:
    st.success(...)
    st.rerun()          # ← raises RerunException; the pass ENDS here
auto_opened = run_auto_paper_entries(df, auto_paper_controls)
```

`st.rerun()` raises, so **whenever any trade auto-closes, no entry is evaluated
in that cycle.** Entries resume on the next refresh, against a reloaded frame
and reloaded paper state.

A headless loop written the obvious way — exits then entries in one pass — would
open trades the dashboard would not have opened, on the same input. This is a
genuine behavioural difference, not an implementation detail.

**S2.2 must decide explicitly** whether to replicate this or fix it. The
recommendation is **replicate it in S2.2, then change it deliberately in a later
session with the counterfactual logged (I6)** — parity first, improvement
second. Fixing it during extraction makes S2.3 unable to distinguish "port
error" from "intended improvement", which defeats the phase.

### 4.2 Ordering: exits always precede entries

Verified at `dashboard.py:9399-9412`. This matters because an exit frees
capacity that `max_daily` and `MAX_ACTIVE_PAPER_TRADES` gate on. Reversing the
order changes which candidates are eligible within the same cycle.

### 4.3 Automation only runs on the Trading page

The trigger sits after early returns for Validation, Replay, Regression,
Reports, and Learning (`dashboard.py:9331-9372`). Each returns when its cache
loads.

**Consequence, and it is worse than "a function of browser uptime":** paper
trading is a function of browser uptime **and which page the operator has
selected**. An operator reviewing the Validation page for an hour opens and
closes nothing. There is no warning and no record that automation was inactive —
the gap is indistinguishable from a session with no qualifying setups.

This alone justifies the phase. It should be stated in the S2.4 retirement
criteria as the specific defect being retired.

## 5. Proposed S2.2 shape

```
app/runtime/headless_paper.py     new — the second caller
  load_controls()                 shared tier-2/3 resolution (§3.1)
  build_automation_frame()        loader + the 4 enrichments (§2 steps B-C)
  run_cycle()                     exits → rerun-equivalent guard → entries
  main()                          scheduler loop, market-hours aware

app/dashboard.py                  refactor only:
  _render_auto_paper_controls()   delegates defaults to load_controls()
  the 4 enrichments               moved to a shared module, st.* calls replaced
                                  by return-value reporting
```

**Constraints for S2.2:**

1. **Move, do not rewrite.** The 4 enrichment functions relocate verbatim except
   for the 2 cosmetic `st.*` calls, which become returned warnings the caller
   renders. A rewrite makes S2.3 meaningless.
2. **One source of truth for controls** (§3.1) — both callers import the same
   resolver.
3. **No new decision logic, no reordering, no "while we're here" fixes.**
   Anything that changes a decision belongs in a later session behind a flag (I6).
4. `REAL_TRADING_ENABLED` stays false (I4). Note that
   `_add_real_trade_readiness` calls `_real_loss_limit_reached()`, which uses the
   linear path deprecated in S1.6 — the headless caller inherits this dependency
   and must not "fix" it here.

## 6. What S2.3 must assert

Parity is the phase's entire quality guarantee, so the harness must compare more
than final decisions.

| Layer | Assertion |
|---|---|
| Controls | Resolved dicts are **identical**, including when the JSON is absent |
| Frame | The assembled frame is identical across all 31 columns + `Price`, including the 3 enrichment-produced columns |
| Decisions | Same symbols opened, same closed, **same order**, same reasons |
| Skips | `SKIPPED`/`BLOCKED` reason strings match — a trade blocked for a *different reason* is a divergence even when the outcome matches |
| Cycle semantics | On a cycle where an exit fires, the headless path evaluates **no entries** (§4.1) |
| State | Resulting `paper_trade_state.json` is byte-identical |

The skip-reason row matters most: outcome-only comparison will pass while the
two paths block the same trade for different reasons, and that difference will
surface later as a divergence under different market conditions.

**Fixture source:** the archived scanner rows in Neon (`candidate_snapshot`,
4,836 rows) provide real frames. `paper_trades` (12 rows) provides known
outcomes to reconcile against. Both are read-only.

## 7. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Controls drift between two default implementations | **High** — silent, and invisible to a JSON-present test | §3.1 shared resolver; S2.3 tests the JSON-absent case explicitly |
| Missing enrichment columns silently produce `None` and different decisions | **High** | §3.2; S2.3 asserts the frame, not just decisions |
| `st.rerun()` semantics not replicated | **High** | §4.1; explicit S2.3 assertion |
| Two writers to `paper_trade_state.json` during the S2.4 parallel run | **High** | Headless must run in a **dry-run/shadow mode** during S2.4, writing to a separate state file. Not yet specified — **S2.2 must design this** |
| Scanner file staleness differs between callers | Medium | Both read the same `scanner_output.xlsx`; assert the generation stamp |
| Market-hours/EOD timing differs from render cadence | Medium | Headless scheduler must use the same 09:45–15:30 / 15:55 ET logic in `paper_automation_support.py`, not its own |

The parallel-run collision risk deserves emphasis: S2.4 runs both paths for 3–5
sessions. If both write live paper state, they will interfere and the
comparison is void. **A shadow-write mode is a prerequisite for S2.4 and must be
built in S2.2**, not improvised later.

Phase 2's framing assumed a large extraction. The measurement in §1 says

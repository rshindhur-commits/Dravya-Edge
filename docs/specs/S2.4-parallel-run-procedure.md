# S2.4 — Parallel-Run Procedure

**Session:** S2.4. Done when: "Zero diffs across all sessions" over 3–5 real
trading sessions with both paths running.

**Status: tooling and procedure built. The 3–5-session run itself has not
happened** — it requires real elapsed calendar time with the market open,
which this or any single session cannot fabricate. This document is what to
run, and the finding that makes running it safely non-obvious.

---

## 1. Finding: shadow-mode state separation is not side-effect isolation

S2.2 built `PAPER_TRADE_STATE_FILE_OVERRIDE` so the headless caller writes its
trade ledger to a separate file, never colliding with the dashboard's live
`paper_trade_state.json`. **That only isolates the ledger.** Verified against
`paper_trade_manager.py`, `open_paper_trade`/`close_paper_trade` unconditionally
also:

- Send a real Telegram message (`maybe_send_paper_entry_alert` /
  `maybe_send_trade_exit_alert`) — gated only by `TELEGRAM_ALERTS_ENABLED`
- Queue a real Neon write (`persist_completed_trade`) — gated only by
  `DB_WRITE_ENABLED`
- Append to `data/daily/<date>/paper_trade_events.csv` — **the same file for
  both paths**, keyed by trading day, with no field identifying which process
  wrote a row

**Running the headless caller against this repo's live `.env`
(`TELEGRAM_ALERTS_ENABLED=true`) would double-send a real Telegram message for
every shadow decision.** This is not a hypothetical — it is the current
`.env`'s actual configuration. Do not launch the headless process with the
dashboard's environment.

### Required launch configuration

The headless process needs its **own** environment, distinct from whatever the
dashboard is running with:

```powershell
$env:TELEGRAM_ALERTS_ENABLED = "false"
$env:DB_WRITE_ENABLED = "false"
$env:PAPER_TRADE_STATE_FILE_OVERRIDE = "app/state/paper_trade_state.headless_shadow.json"
python -m app.runtime.headless_paper
```

Leave the dashboard's own environment (and its `.env`) untouched — it keeps
sending real alerts as it does today. Only the headless side is muted.

The `paper_trade_events.csv` intermixing is not worth solving for a 3–5 day
comparison: `tools/headless_parity_diff.py` compares the two **state files**
directly, which are cleanly separated and sufficient. Note it as a real gap
rather than fix it under I2/I6 pressure — if Phase 2 ends with the headless
path retired *in*, the CSV writer should gain a provenance column at that point,
not before.

## 2. Daily procedure

Each session day, with the dashboard running normally and the headless process
running per §1:

1. At end of day, run:
   ```powershell
   python tools/headless_parity_diff.py `
     --live app/state/paper_trade_state.json `
     --shadow app/state/paper_trade_state.headless_shadow.json
   ```
2. Exit code `0` = clean. Non-zero = read the printed report; every mismatch
   is one of three categories (`only_in_live`, `only_in_shadow`, `mismatched`
   with the specific field and both values).
3. **Do not delete the shadow file between sessions.** Copy it aside
   (`paper_trade_state.headless_shadow.<date>.json`) before the next session
   starts, so each day's comparison is against that day's trades only —
   otherwise day 2's diff also re-compares day 1's already-reconciled trades.
4. Record the day's exit code and any diffs. 3–5 consecutive clean days is the
   done-condition.

## 3. What a diff would mean

Per S2.1 §6, both paths call the identical `run_auto_paper_entries` /
`run_auto_paper_exits`. A diff therefore is not a strategy-logic bug — it is
one of:

- **Input-assembly divergence** — the two frames disagreed (missing
  enrichment column, stale scanner file read by one side, controls resolved
  differently). Check the frame, not the decision logic.
- **Timing divergence** — the headless poll cadence (`HEADLESS_PAPER_POLL_SECONDS`,
  default 60s) sampled a different scanner snapshot than the dashboard's render
  cycle did. A trade opened by one path a scan-cycle before the other is
  expected under close timestamps; `headless_parity_diff.py`'s
  `CLOSE_TIME_TOLERANCE_SECONDS` (120s) absorbs small gaps but will still flag
  the underlying trade if only one side has it at all.
- **The `st.rerun()` skip (S2.1 §4.1) firing differently** — if a close and an
  eligible entry land in the same scan cycle, both paths should skip the entry
  that cycle (S2.3 proved this in isolation). A live diff here would mean the
  parity harness missed something real.

## 4. Retirement (only after zero diffs across 3–5 sessions)

Retiring the dashboard path means: `dashboard.py`'s Trading page stops calling
`_dispatch_trading_page_automation`, and `app/runtime/headless_paper.py`
becomes the only writer to the real `paper_trade_state.json` (remove the
`PAPER_TRADE_STATE_FILE_OVERRIDE` for production use, run it as a standalone
process per `docs/OPERATIONS.md`).

**Not done in this session** — it is gated on the run in §2 actually completing
clean, which has not happened yet. Flipping it now would violate the session's
own done-condition.
